巡检策略
两种巡检策略怎么选？
🔋 智能巡检（推荐）
启动后密集巡检约 20 次摸清各模型状态，之后自动休眠，每天中午 12 点自动复查一次。
优点：几乎不额外消耗上游免费额度，路由器负载极低，适合长期挂机。
缺点：休眠期间模型状态不是实时的，故障发现有延迟（随时可点右上角"立即检测"手动刷新）。
📡 持续监控
每 5 分钟不间断巡检所有模型，永不休眠。
优点：模型状态接近实时，异常能在几分钟内发现。
缺点：持续消耗上游额度和路由器资源，对免费额度不友好，长期挂机可能触发上游限流。

⚙️ 网关设置
🗂️ 响应缓存（语义级）
相同或近似的重复提问直接用缓存秒回，不再消耗上游额度。近似匹配用 simhash 指纹（零依赖，软路由友好）。
统计加载中…
💰 预算护栏（每日成本）
按模型参考价累计当日成本（USD）。达到预警比例在面板顶部提醒；「超限拦截」模式下当日超限的请求直接返回 429。上限填 0 表示不限。
🚦 并发护栏
限制同时处理的请求数，防止软路由内存被打满。0 表示不限。各提供商的单独并发上限在「编辑提供商」里设置（max_concurrency）。
🛡️ 严格能力矩阵
开启后，路由候选会严格过滤掉不满足所需能力的模型。例如请求带图片（视觉）时，不会把纯文本模型当候选，避免触发「该模型不支持图像」的 400 错误。关闭则沿用原版宽松匹配。
🛡️ 安全套件
SSRF 严格出站模式
网关转发到上游前校验目标 IP，默认已拦截回环/链路本地（含云元数据 169.254.169.254）防 SSRF 泄露。开启严格模式会额外拦截 RFC1918 私网（如 192.168.x），仅允许公网——仅在你只用公有云 provider、且不需要连局域网自托管（Ollama 等）时开启。
客户端 IP 白名单
留空=不限制（默认）。填写后仅列表内 IP/CIDR 可调用 /v1/* 代理，其余返回 403。支持裸 IP 或 CIDR，逗号/换行分隔。
封禁的 Provider
被封禁的 provider 永不参与路由/探测/模型列表。仅影响运行态、不删配置；从列表移除即恢复。PII 脱敏开关在「编辑提供商」处。
🔔 事件钩子（Webhook）
请求成功/失败时向你的 URL POST 一条 JSON（可接飞书/钉钉/n8n 等）。安全限制：https 任意地址；http 仅限本机 127.0.0.1。填写密钥后会附带 HMAC-SHA256 签名头 X-Hook-Signature。
🔑 虚拟密钥（子密钥）
虚拟密钥是主管理密钥的子密钥：可下发给不同应用/用户，各自带每日配额（请求数 / Token）与模型白名单。超额或到期自动 429 拒绝。密钥明文仅在创建时显示一次，请妥善保存。

⚙ 高级鉴权设置（自定义鉴权头）
特殊提供者填自定义头：gemini 用 x-goog-api-key，部分用 x-api-key / api-key
头名=Authorization 且前缀留空自动加 Bearer ；填 none 表示密钥直接作为头值（不加 Bearer）
Claude 原生：直连 api.anthropic.com 等原生接口，网关自动做请求/响应/流式格式转换；鉴权头填 x-api-key、前缀 none；网关会自动附加 anthropic-version 头。工具调用（tool_use）也已翻译。
OpenAI Responses 原生：直连实现了 Responses API（/v1/responses）的端点（如部分 OpenAI 兼容网关/代理），网关自动把 OpenAI Chat 协议与 Responses 协议互转（system→instructions、max_tokens→max_output_tokens、function_call↔tool_calls、流式事件翻译）。
通用协议适配器：给那些「压根不是 OpenAI 接口」的站点用（自定义路径、令牌握手、自定义请求/响应字段）。网关按一份声明式规格自动完成双向协议转换。要接入清单以外的站点、或上游改版导致失效时，把规格写进数据目录的 adapters.json 即可自行修正，无需等新版本。
对支持推理的模型（Claude extended thinking / Gemini thinking）设置思考 token 上限，防止“想太久烧太多”。仅 claude / gemini 格式生效，openai 推理模型走其原生参数、此处不注入。需小于该请求的 max_tokens。
仅当提供者本身支持匿名访问但需固定 key 时填写；普通免 Key 提供者留空即可。
